# Install LAD Factory

Use this entrypoint once per package copy, or when deliberately changing its host binding.
Installation prepares files. `prompts/setup.md` later initializes each run.
Do not start a run, model call, service, scheduler, or Goal during installation.

## Discover

Read `AGENTS.md`, `context/routing.md`, `docs/setup.md`, and `templates/installation-profile.md`.
Inspect the selected host's optional adapter source, when available, under `adapter-templates/`.
Read the target workspace's applicable instructions before proposing target changes.

Use read-only existing metadata to discover host versions, configured model lists, native configuration identities, and available tools.
For local models, inspect existing hardware, model metadata, and served context settings when access is authorized.
Distinguish installed, authenticated, configured, and unknown. A listed model is not proof of usable access.

Do not read secret values, install dependencies, download models, start services, or make inference or paid API calls.
Do not run benchmarks, calibration, qualification exercises, compatibility probes, or throughput measurements.
Record evidence as observed, documented, user-confirmed, or unknown, with dates and limitations.

## Ask and recommend

Ask only consequential questions that discovery cannot answer. Cover these together when needed:

- Which host and permitted model providers may own stages or helpers? Is a separate harness transport authorized?
- What matters most: quality, cost, speed, privacy, or local-only operation? What resource and spending limits apply?
- Which paths and native configuration files may installation write? Which continuation mode does the user prefer?

Match role needs to permitted available model metadata and those priorities.
Recommend explicit stage and helper bindings with their evidence and limitations. Do not claim an optimal ranking.
Use dated primary documentation for capability claims. Artificial Analysis may be an optional secondary reference, never a dependency.

The Codex CLI adapter supplies the shipped Sol/Astra/Luna defaults. Other profiles may use other models and supported efforts.
Keep every stage, review boundary, outcome, and finite cap. Do not offer a collapsed or lightweight workflow.

Show the proposed profile, selected adapter, native file destinations, and unresolved capabilities before writing them.
Proceed within existing user authorization. Obtain only missing authority for consequential host or target configuration changes.
Do not install a new runtime, daemon, plugin framework, or universal bridge.

## Install authorized files

1. Reconcile any existing installation and active run before writing.
2. Fill `templates/installation-profile.md` as private `installation/profile.md` with an explicit revision.
3. Merge the complete primary binding guide and every selected secondary binding guide into one self-contained `installation/adapter.md`.
4. Copy required native starter files into authorized installation or native configuration paths outside `adapter-templates/`.
5. Point native files to the shared pinned stage prompt or helper work order supplied at dispatch.
6. Record exact native file identities and setting precedence in the profile.
7. Check required paths, completed bindings, native syntax, and links without inference.
8. Report prepared files, unresolved capabilities, and the per-run `prompts/setup.md` entrypoint.

For cross-harness installations, merge the full shared cross-harness contract into that same `installation/adapter.md`.
Give each guide and contract an identified section with its source and revision. Resolve source-relative paths to installed paths or documentation URLs.

Do not retain separate mutable guide imports. The run snapshot pins this single merged guide with the profile.
Native configuration files remain separate. Record and verify their exact content identities as required by the profile.

Never replace existing instructions or configuration wholesale. Preserve unrelated entries and user changes.
Native configuration may override requested models or efforts. Record and check effective settings before dependent dispatch.

Provider, permission, and tool inheritance follow the actual host. A profile cannot grant unavailable controls.
Model IDs alone never enable cross-harness transport. Such transport needs an explicit adapter binding and authorization.

Installation may finish with unknown runtime capabilities. Label the installation prepared and name execution gates honestly.
No trial LAD run or inference test is required to complete installation.

## Retain or remove adapter sources

The optional `adapter-templates/` folder contains source guides and starters only.
After copying every required selected guide and native file, the user may remove that entire folder.
Check that installed runtime instructions and native files have no required links or imports into it.

Do not delete the folder automatically. Reconfiguration after cleanup deliberately restores the needed source version.
Changing an installation creates a new profile revision for future runs. It never changes an active run's pinned instructions.
Do not rewrite native files used by an active run. Prepare separate future-run files or wait for the run to close.
